# BookingLight — сервис краткосрочной аренды жилья

Учебный проект для студентов 3 курса по изучению микросервисной архитектуры на платформе **.NET 10**.

Что вы отработаете в этом задании:

- проксирование запросов через API Gateway (YARP);
- реализацию бизнес-логики в отдельном микросервисе;
- работу с EF Core InMemory;
- командную работу через Git: ветка → Pull Request → Code Review.

---

Клиент (Postman, Visual Studio `.http`-файлы, браузер) обращается **только к API Gateway**. Шлюз перенаправляет запросы на внутренние микросервисы. Прямые обращения к сервисам на портах 5010 и 5020 допустимы только для отладки.

| Сервис | Порт | Назначение | Статус |
|---|---|---|---|
| `Gateway.API` | `https://localhost:5000` | Единая точка входа (YARP) | Частично готов, **есть задание** |
| `Announcements.API` | `https://localhost:5010` | Объявления о жилье | ✅ Полностью готов |
| `Bookings.API` | `https://localhost:5020` | Бронирование жилья | 🛠️ **Шаблон-задание** |

Оба сервиса хранят данные в памяти (EF Core InMemory). Строки подключения не нужны, при каждом перезапуске данные сбрасываются.

### ⚠️ Правила работы с Git

Прямые коммиты в ветку `master` **категорически запрещены**.

1. Склонируйте репозиторий. Если прав на запись нет, сначала сделайте **Fork** и работайте в своём форке.
2. Создайте рабочую ветку от `master` с названием `feature/bookings-implementation`.
3. Вся работа ведётся только в этой ветке. Коммитьте небольшими логичными частями с понятными сообщениями (например, `Add YARP route for bookings`).
4. Сдача происходит через **Pull Request** из вашей ветки в `master`.

## 🚀 Запуск и окружение

**Требования:** Visual Studio 2026 (или другая IDE) и .NET 10 SDK.

В решении настроен **Multi-project Startup**. При нажатии `F5` запускаются сразу три приложения:

- `Gateway.API` — `https://localhost:5000`
- `Announcements.API` — `https://localhost:5010`
- `Bookings.API` — `https://localhost:5020`

Если браузер или клиент ругается на сертификат, выполните один раз:

```
dotnet dev-certs https --trust
```

**Быстрая проверка, что всё работает:** откройте `https://localhost:5000/api/announcements`. Должен вернуться JSON со списком из 4 объявлений.

## 📝 Техническое задание

### Шаг 1. Настройка API Gateway (YARP)

В проекте `Gateway.API` откройте `appsettings.json`. По аналогии с маршрутом для сервиса объявлений добавьте `Route` и `Cluster` для сервиса бронирования:

- запросы `/api/bookings/{**catch-all}` должны проксироваться на `https://localhost:5020`.

Места для вашего кода помечены комментариями `// TODO СТУДЕНТУ`. После выполнения задания удалите эти комментарии.

Документация: [YARP Reverse Proxy](https://microsoft.github.io/reverse-proxy/).

### Шаг 2. Реализация сервиса бронирования (`Bookings.API`)

Вам предоставлен шаблон: модель, интерфейс сервиса, контроллер и регистрация в DI уже готовы. Методы сервиса — заглушки. Нужно:

1. Добавить в проект пакет `Microsoft.EntityFrameworkCore.InMemory`, создать `DbContext` с `DbSet<Booking>` и зарегистрировать его в `Program.cs`.
2. Реализовать `BookingService.GetBookingsByAnnouncementAsync` — возвращает все бронирования указанного объявления.
3. Реализовать `BookingService.CreateBookingAsync` — сохраняет бронирование в базу, сгенерировав `Id`.
4. Реализовать **валидацию** (см. ниже) и при нарушении выбрасывать `ArgumentException` или `InvalidOperationException` с понятным сообщением. Контроллер уже превращает их в ответ `400 Bad Request`.

#### 🔑 Правила валидации при создании брони

| № | Правило | Результат |
|---|---|---|
| 1 | `CustomerName` не пустое | иначе `400` |
| 2 | `EndDate` строго позже `StartDate` | иначе `400` |
| 3 | Для того же `AnnouncementId` нет бронирований, пересекающихся по датам | иначе `400` |

**Условие пересечения периодов** `[StartDate, EndDate)`: новая бронь пересекается с существующей, если

```
новая.StartDate < существующая.EndDate  И  новая.EndDate > существующая.StartDate
```

Заезд в день выезда предыдущего гостя **допустим**: одна бронь может заканчиваться `10.10`, а следующая начинаться `10.10`. Брони на **разные** объявления друг другу не мешают.

Поле `TotalPrice` в рамках базового задания принимается от клиента как есть.

### Шаг 3. Тестирование системы

Все запросы отправляйте **через шлюз** (`https://localhost:5000`). Можно использовать Postman или создать в Visual Studio файл `requests.http`:

```http
@host = https://localhost:5000

### Список объявлений
GET {{host}}/api/announcements

### Бронирования объявления (сначала пусто)
GET {{host}}/api/bookings/announcement/11111111-1111-1111-1111-111111111111

### Создать бронь
POST {{host}}/api/bookings
Content-Type: application/json

{
  "announcementId": "11111111-1111-1111-1111-111111111111",
  "customerName": "Иван Петров",
  "startDate": "2026-10-10",
  "endDate": "2026-10-15",
  "totalPrice": 27500
}
```

#### Обязательные тест-сценарии

Предположим, бронь `10.10 → 15.10` для объявления `1111…` уже создана.

| Сценарий | Ожидаемый результат |
|---|---|
| Бронь `10.10 → 15.10` (те же даты) | `400` |
| Бронь `12.10 → 20.10` (пересечение справа) | `400` |
| Бронь `05.10 → 12.10` (пересечение слева) | `400` |
| Бронь `11.10 → 13.10` (внутри существующей) | `400` |
| Бронь `01.10 → 30.10` (накрывает существующую) | `400` |
| Бронь `15.10 → 20.10` (заезд в день выезда) | `201 Created` |
| Бронь `01.10 → 10.10` (выезд в день заезда) | `201 Created` |
| Бронь `10.10 → 15.10` для объявления `2222…` | `201 Created` |
| `EndDate` раньше `StartDate` | `400` |
| Пустое `CustomerName` | `400` |
| `GET /api/bookings/announcement/{id}` после создания | список с созданными бронями |

Пока метод `CreateBookingAsync` не реализован, `POST /api/bookings` возвращает `501 Not Implemented`. После вашей реализации этот ответ появляться не должен.

### ⭐ Дополнительные задания (по желанию)

- Проверять, что объявление с указанным `AnnouncementId` существует: запросить его у `Announcements.API` через `HttpClient` (`IHttpClientFactory`). Если нет, вернуть `404` или `400`.
- Считать `TotalPrice` на стороне сервиса: количество ночей × `PricePerNight` из объявления.
- Добавить эндпоинт `DELETE /api/bookings/{id}` для отмены брони.
- Написать unit-тесты на `BookingService` (xUnit), покрывающие таблицу сценариев выше.
