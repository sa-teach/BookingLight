# BookingLight - Сервис краткосрочной аренды жилья

Учебный проект для студентов 3 курса по изучению микросервисной архитектуры на платформе **.NET 10**.

---

### 🗺️ Архитектура системы

Вся работа с системой со стороны клиента (Swagger, Postman) идет строго через единую точку входа — API Gateway. Шлюз автоматически перенаправляет запросы на соответствующие внутренние микросервисы.

### 👥 Распределение ролей и регламент разработки

* **Архитектор / Преподаватель (@sa-teach)**: 
  * Разработал общую архитектуру решения и базовый каркас.
  * Полностью реализовал `Announcements.API` (Сервис объявлений).
  * Выполняет Code Review, утверждает Pull Request'ы и выставляет оценку.
* **Разработчик / Студент**:
  * Настраивает маршрутизацию для своего сервиса на API Gateway.
  * Полностью реализует бизнес-логику в проекте `Bookings.API` (Сервис бронирования).

⚠️ **Важное правило**: Прямые коммиты в ветку `master` **категорически запрещены**. 
1. Студент должен создать свою рабочую ветку от `master` с названием `feature/bookings-implementation`.
2. Вся работа ведется только в ней.
3. Сдача проекта происходит путем открытия **Pull Request (PR)** в ветку `master`.

### 🚀 Запуск и окружение

В решении настроен **Multi-project Startup** (Множественный запуск проектов) в Visual Studio 2026. При нажатии `F5` запускаются одновременно 3 приложения:
* **Gateway.API** — `https://localhost:5000` (Внешний адрес системы)
* **Announcements.API** — `https://localhost:5010` (Внутренний сервис объявлений)
* **Bookings.API** — `https://localhost:5020` (Внутренний сервис бронирования)

*Для хранения данных микросервисы используют EF Core c провайдером InMemory (база данных в оперативной памяти), конфигурация строк подключения не требуется.*

### 📝 Техническое задание для студента

Вам необходимо доработать архитектурный каркас и реализовать логику бронирования жилья.

#### Шаг 1. Настройка API Gateway (YARP)
В проекте `Gateway.API` откройте файл `appsettings.json`. По аналогии с Сервисом Объявлений, добавьте конфигурацию маршрутизации (Route и Cluster) для Сервиса Бронирования:
* Все внешние запросы, начинающиеся с `/api/bookings/`, должны проксироваться шлюзом на внутренний адрес `https://localhost:5020`.
* Изучите официальную документацию [YARP Reverse Proxy](https://github.io), если возникнут трудности.

#### Шаг 2. Реализация Сервиса Бронирования (`Bookings.API`)
Вам предоставлен шаблон проекта, в котором объявлены модели и эндпоинты, но методы выбрасывают исключения или возвращают ошибку. Требуется:
1. Реализовать логику `BookingService` для сохранения бронирований в базу данных.
2. **Критически важная бизнес-логика**: При создании бронирования (`POST /api/bookings`) обязательно реализовать валидацию дат (`StartDate` и `EndDate`). Если на указанные даты для данного `AnnouncementId` уже есть существующее бронирование, система должна возвращать ошибку (пересечение дат не допускается).
3. Наполнить эндпоинты в `BookingsController`, связав их с бизнес-логикой сервиса.

#### Шаг 3. Тестирование системы
* Убедитесь, что при отправке запросов на единый порт шлюза (`https://localhost:5000/api/announcements`) вы получаете данные от вашего преподавателя.
* Добейтесь, чтобы ваши эндпоинты бронирования также успешно отвечали через шлюз по адресу `https://localhost:5000/api/bookings/`.
